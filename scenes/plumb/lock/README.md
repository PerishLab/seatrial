# Lock admission conformance

These optional scenes exercise formally distributed Plumb and Ectropy through
their public CLIs. They do not link product crates, build either product or use
a product-source checkout. The tiny Rust workspace is diagnostic input to
Plumb's documented compiler-backed behavior; Plumb owns its compilation.

`joint` requires a Plumb non-stable artifact containing native review Guard
admission and an Ectropy artifact containing the shared lock syntax role.
It checks data-Mutex nonclassification, successful admission and observed exact
proof reuse, cropped workflow inputs, new unreviewed native calls, exact
source-bound reviews, changed/restored protocol evidence, real Ectropy ban and
file grant participation, and directory-grant refusal. Native fixture helpers
are compiled, never executed; this proves admission behavior, not lock
algorithms, business roles or cleanup safety.

`required` additionally requires the Plumb artifact's carried policy to select
both `PerishLab/plumb` and `PerishLab/runseal` with default and all-features coverage.
It checks each identity in an independent synthetic source repository and diagnostic
namespace, recording the repository with its observations. It refuses deleted
or disabled declarations, either narrowed feature selection and missing Ectropy
participation, then restores the exact accepted input. The local synthetic Git
identity exercises the policy matcher; it is not a real GitHub landing canary.

Both cases start disabled. Explicitly select them only for the promised tool
combination. Missing support or a missing carried scope fails; it is never
skipped into a pass. These prospective cases are not Bug exceptions against
older products that never promised the capability. Source delivery does not
establish scene distribution, successful formal execution or promotion.
Seatrial #45 owns this source result; Plumb #528 retains those execution,
activation and actual landing obligations under the global .github #152 plan.
Seatrial #49 extends the source assertions to Runseal; Plumb #534 retains its
distributed scene, formal combination, activation and landing obligations. A
Plumb artifact selecting only the original Plumb scope cannot pass this extended
required scene. Existing historical passes retain their exact scene identity.

The parent Plumb bundle retains the canonical writer case ID and adds lock/joint and
lock/required. Plumb follows its non-stable channel, Ectropy its current stable
channel, and the runtime follows the existing Plumb Images declaration.
No tool version or first-party image is pinned by a scene.

The runner verifies and records actual archives, seals, versions, commits,
image and scene identities. Both tool executables are mounted read-only and
checked against their resolved versions; actual binary hashes are printed.
Each case uses its own labelled lane volume, with no host port or live account.
The ordinary lane teardown and record own cleanup and final qualification;
a printed case observation does not issue a promotion credential.

For an explicit local scene development run, use the public interface:

```sh
seatrial run --pins seatrial.toml --scenes scenes/plumb \
  --case lock/joint --case lock/required --report NEW_FILE.json
```

A local scene override is development evidence. Formal qualification also needs
its distributed scene generation and formally admitted runner. Keep failures
for older tool combinations as failures with cleanup evidence; never relabel
them as successful execution of these cases.
